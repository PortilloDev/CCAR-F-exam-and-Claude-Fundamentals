# Lecture 57: Intro: Configuration That Gets Followed

**Section:** Claude Code in a Team  
**Lecture ID:** 58006593

---

## Transcript

A team convention may work in your Claude Code session and be absent from a colleague's — not because of different wording, but because the file is personal rather than shared with the project.

### What this chapter covers

- **User, project, and directory levels** for CLAUDE.md instruction files.
- Which settings are personal vs. shared via version control.
- Writing rules with specific requirements and clear alternatives (not vague prohibitions).
- Keeping the main instruction file focused and checkable.
- Splitting conventions into imported topic files vs. path-specific rules.
- Why an **import always loads** its contents at startup, while a **path condition** controls when a rule applies.

**Goal:** Organise shared instructions and choose the scope and wording that fit each convention.
